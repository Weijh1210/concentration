# Concentration 分阶段开发计划

> 状态：方案草案；2026-10-11。当前只完成设计文档，不初始化项目或创建云端资源。

## 1. 阶段与交付

| 阶段 | 目标 | 主要交付 | 完成门槛 |
| --- | --- | --- | --- |
| 0. 方案确认 | 锁定首版边界与关键决策 | PRD、架构、数据库、决策记录 | 用户确认第 7 节决策；风险有验证计划 |
| 1. 工程基础 | 初始化可运行 App | Expo Router、TypeScript、lint/typecheck/test、环境变量示例、CI 基础 | iOS/Android 开发构建可启动，检查通过 |
| 2. 离线核心 | 游客可完整专注 | SQLite 迁移、任务、状态选择、规则推荐、Start Mode、计时器、反馈、历史统计 | PRD 验收场景 1/2；状态机和时间计算自动化测试通过 |
| 3. 云端同步 | 账号与多设备数据 | Supabase Auth、数据库迁移/RLS、outbox、游客导入、冲突处理 | 场景 3/4；RLS、幂等、冲突集成测试通过 |
| 4. 体验与真机验证 | 稳定可试用 MVP | 场景、白噪音、无障碍、错误恢复、性能和真机测试 | iOS/Android 后台/锁屏/强杀矩阵验证；无假功能 |
| 5. 发布准备 | 小范围测试发布 | 隐私说明、账号删除路径、监控、商店素材和发布清单 | 用户批准任何线上创建/部署；发布检查通过 |
| 6. 后续探索 | 个性化与 Together | AI 推荐实验、Realtime 方案、Growth 扩展 | 基于使用数据和隐私评估另立需求 |

阶段 2 可先使用明确标注的本地 Mock Auth 来验证游客流程；阶段 3 接入真实 Supabase。Mock 不得伪装成云端同步已完成。

## 2. 优先实现顺序

1. 类型、领域模型和状态机。
2. SQLite schema 与 repository；本地任务 CRUD。
3. 规则推荐、Start Mode 和计时器；锁屏/重启恢复。
4. 会话反馈、历史与真实统计。
5. Auth、云端 schema/RLS、同步 outbox 与冲突界面。
6. 白噪音、场景和真机行为验证。

## 3. 测试策略

- 纯单元测试：推荐规则、状态转换、时长累计、暂停/恢复、到时截断、统计口径。
- 本地集成测试：SQLite 事务、迁移、outbox 重试和游客导入幂等。
- 云端集成测试：RLS 跨用户拒绝、revision 冲突、重复请求幂等、软删除同步。使用测试项目或本地 Supabase，不指向生产。
- 真机手动矩阵：iOS/Android 前后台切换、锁屏、强杀重启、系统时间修改、网络断开恢复、音频中断。
- 每阶段运行适用的 `typecheck`、`lint`、自动化测试和构建检查，记录命令、结果与未验证项。

## 4. 关键技术风险

| 风险 | 发生阶段 | 决策/验证点 |
| --- | --- | --- |
| 后台计时显示与提醒差异 | 2、4 | 时间戳为真值；通知不保证准时；真机矩阵 |
| 离线多设备会话冲突 | 3 | 在线唯一约束；离线冲突保留并提示处理 |
| 游客导入重复或丢失 | 3 | UUID 幂等与可重试导入；失败不删除本地 |
| 白噪音版权、包体和后台行为 | 4 | 使用明确许可资源；真机验证后台播放 |
| 云端成本与地域 | 3、5 | 用户先选地域和预算；开发环境与生产分离 |
| 认证方式的送达率 | 3 | email OTP 真实设备和目标地区验证 |

## 5. 需要用户手动创建的第三方账号和配置

| 项目 | 何时需要 | 用户需手动完成 | 提供给项目的配置 |
| --- | --- | --- | --- |
| Git 代码托管（GitHub/GitLab 等） | 阶段 1，若需远端协作 | 创建私有仓库、设置协作者与分支保护 | Git remote URL；无需分享个人 access token |
| Expo 账号 / EAS | 阶段 1 或真机云构建时 | 注册账号、创建 Expo project；按需要配置 EAS | Expo project ID、owner；构建凭据只放平台安全存储 |
| Supabase | 阶段 3 | 建开发 project；发布前另建生产 project，选地域并配置预算告警 | `EXPO_PUBLIC_SUPABASE_URL`、`EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`；服务端密钥仅放安全环境 |
| 邮件服务 | 认证邮件超出 Supabase 默认能力或正式发布时 | 选择并配置 SMTP provider、发件域名 DNS | SMTP 凭据存 Supabase secret，不进 App 或 Git |
| Apple Developer Program | iOS TestFlight/商店发布前 | 注册团队、设置 Bundle ID、证书与商店资料 | Apple team ID、Bundle ID；密钥不写入仓库 |
| Google Play Console | Android 商店发布前 | 注册开发者、配置应用签名和商店资料 | Android package name；签名密钥安全托管 |
| 域名与隐私政策托管 | 正式发布前 | 购买/控制域名、发布隐私政策与支持页面 | 对应 URL；购买前先确认预算 |
| 模型 API provider | 后续 AI 阶段 | 自选供应商账号、预算和数据处理条款 | API key 只放 Edge Function secret |
| 音频素材来源 | 阶段 4 | 提供自有音频或确认可商用许可素材 | 素材文件及许可证记录 |

本地开发可先不创建 Apple/Google 商店账号、模型供应商账号或付费服务。Supabase 和 Expo 的可用额度、定价和政策会变化，创建前应以各平台当前条款为准。不得把真实 key 写入 `.env.example` 或提交 Git。

## 6. 建议的环境变量

```dotenv
# 客户端可公开配置，不是秘密；只填开发环境值
EXPO_PUBLIC_SUPABASE_URL=
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=

# 仅服务端 Edge Function secret，不进入客户端 bundle
MODEL_API_KEY=
```

`MODEL_API_KEY` 在 MVP 规则推荐阶段不需要设置。密钥只通过各平台 secret 管理，不在文档、日志或仓库内传递。

## 7. 初始化前需要确认的决策

1. **首发平台**：iOS 与 Android 同步开发，还是先选一端做内测？建议双端代码、先用手头真机做第一轮验证。
2. **登录方式**：建议 email OTP；是否需要密码或 Apple/Google 登录？这影响认证配置和审核工作。
3. **游客数据迁移**：建议首次登录时询问是否导入本机游客数据；已有云端数据时合并且保留冲突提示。
4. **云端地域与预算**：开发 Supabase project 放在哪个地域、可接受的月度成本上限是多少？创建资源前必须确认。
5. **统计口径**：建议只把 `finished` 会话计入专注总时长，跨午夜会话归开始日，启动 5 分钟计入时长。是否符合预期？
6. **后台白噪音**：首版是否要求锁屏后持续播放？若要求，需接受额外平台配置和真机验证。
7. **品牌与内容**：是否已有视觉规范、图标、音频素材和隐私政策主体？没有时先采用可替换的开发占位资源，并明确标注。

确认后才能进入阶段 1；创建付费资源、生产项目或部署线上服务需另行明确授权。
