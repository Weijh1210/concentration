# Concentration 产品需求文档（MVP）

> 状态：MVP 产品目标；2026-10-11。当前本地前端的实际实现状态见 [README.md](../README.md)。云端本地实现已完成，线上项目未配置；AI 推荐设计见 [AI_RECOMMENDATION.md](AI_RECOMMENDATION.md)。

## 1. 产品目标

Concentration 是面向高强度自主学习者的 AI-powered Focus System。它以 **Focus Session** 为核心，把“想做的任务”转成一次能开始、能持续、能复盘的专注行动。规则推荐作为离线基线；本阶段加入用户主动触发的 AI 任务拆解与会话建议，失败时回退规则。

目标用户：考研、考公、语言考试和大学生等自主学习者。核心场景：用户知道要学什么，但启动困难；学习中断后难以恢复；结束后缺少可见反馈。

首版设计原则：从打开 App 到开始专注尽量少于 4 次主要操作；游客可以完整体验核心流程；任务和计时数据真实可追溯；离线可用。

## 2. 核心流程

`Task → State → Recommend → Start Mode → Focus → Finish → Feedback → Personalization`

| 步骤 | 用户行为 | 系统行为 |
| --- | --- | --- |
| Task | 新建或选取任务 | 保存任务；允许跳过任务直接开始一次自由专注 |
| State | 选择当前精力、启动难度和可用时间 | 仅收集推荐所需的最少输入 |
| Recommend | 查看推荐方案 | 展示时长、启动方式、推荐原因；允许手动调整时长 |
| Start Mode | 接受 5 分钟启动 | 启动 5 分钟阶段；结束后选择继续正式专注或结束 |
| Focus | 查看计时，选择环境音 | 可暂停、恢复、提前结束；后台或锁屏后重新打开能恢复准确显示 |
| Finish | 确认本次结束 | 记录实际专注时长与结束原因；到时后进入待确认的结束页 |
| Feedback | 选择完成感受和干扰程度 | 保存反馈，可跳过 |
| Personalization | 查看历史和基础统计 | 用真实会话计算总时长、完成次数和近 7 天趋势；后续推荐可使用历史特征 |

## 3. MVP 功能与验收标准

### 3.1 身份与数据

- 游客模式无需账号，可本地创建任务、计时、反馈和看历史。
- 登录首版建议使用 Supabase Auth 的 email OTP；具体方式需在初始化前确认。退出登录后本地缓存应与账号隔离。
- 游客注册或登录时，明确提示是否把本机游客数据导入账号。导入使用稳定 UUID，重复尝试不得产生重复任务或会话。
- 登录用户的任务、会话和反馈在网络恢复后同步到 Supabase。离线修改保留在设备端并显示“待同步/同步失败”状态。

### 3.2 任务

- 创建、编辑、完成、重新打开和软删除任务。必填标题；可选备注和预估时长。
- 列表区分未完成与已完成；搜索、标签、子任务均不在首版。
- 已完成任务仍可关联历史会话。

### 3.3 推荐与启动

- 状态输入：`energy`（低/中/高）、`start_friction`（低/高）、`available_minutes`（5/15/25/45/60）。
- 规则推荐输出 `planned_minutes`、`use_start_mode`、`reason_code`。规则版本随会话保存，便于解释和后续调整。例：高启动困难优先 5 分钟启动；低精力优先较短会话；时长不得超过用户可用时间。
- Start Mode 固定 5 分钟，结束后明确询问“继续专注”或“结束”。这 5 分钟计入实际专注时长，但与正式阶段分开展示。可跳过 Start Mode。
- 推荐不宣称由大模型生成；界面文案清楚写“根据当前状态推荐”。

### 3.4 专注与声音

- 会话状态：`ready`、`start_mode`、`focusing`、`paused`、`awaiting_finish`、`finished`、`abandoned`。同一设备同一时间最多一个未结束会话。
- 计时基于持久化时间戳和累计时长，不依赖每秒 `setInterval` 累加。暂停不计时；重启后恢复状态；跨系统时间手动修改时提示用户核对。
- 到达计划时长时进入 `awaiting_finish`，不在后台暗中继续增加专注时长；用户可确认结束或选择继续计时。锁屏时及时发出提醒属于平台能力验证项，不作为秒级保证。
- 基础沉浸场景至少包括浅色和深色静态场景；至少一种随包提供、许可清晰的循环白噪音。音频可开关和调节音量。后台持续播放需在真机验证后确定首版承诺。
- 提前结束时记录实际时长和 `end_reason`，不把提前结束伪装成计划完成。

### 3.5 反馈和统计

- 反馈可选：`perceived_focus`（1–5）、`interruption_count`（0/1/2+）、简短备注。允许跳过，稍后可补填一次。
- 历史列表按本地时间展示任务、开始时间、实际专注分钟数、完成状态；可查看详情。
- 基础统计：今日和近 7 天专注时长、完成会话数、连续有专注天数。统计直接由有效会话计算，排除 `abandoned` 和未完成会话；明确时区和统计口径。

## 4. 非目标

首版不实现复杂 AI Agent、好友同步专注、自习室、社交信息流、复杂游戏化、订阅支付、AI 训练或大型虚拟世界。`Together` 和高级 `Growth` 保留架构扩展点，不在界面放无效入口。

## 5. 关键体验与质量要求

- 无网络时核心流程可完成；同步失败不丢本地数据。
- 新用户首次进入可直接以游客开始；关键操作有明确空状态、错误状态和恢复路径。
- 遵守系统文字缩放、屏幕阅读器标签和足够的颜色对比度；声音默认关闭。
- 不把白噪音播放时间等同于专注时长；不以通知送达作为计时真值。
- 数据最小化：仅收集完成核心功能所需数据；提供退出、删除本地游客数据和后续账号删除路径。

## 6. 首版验收场景

1. 游客离线创建任务，选择状态，进入 Start Mode，继续专注，结束并反馈，历史和统计准确。
2. 专注中暂停、锁屏、重启 App 后恢复，暂停时间不计入；提前结束记录真实时长。
3. 离线创建和编辑后登录，同步成功；重复同步不产生重复数据，另一台设备能读取历史。
4. 断网或认证过期时显示同步状态，本地编辑仍可用，恢复网络后重试。
5. 无音频权限或被系统中断时计时不受影响，音频状态能正确恢复或提示。
